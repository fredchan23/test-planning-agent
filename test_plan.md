# Agentic Test Plan: https://healthspan.assurecraft.org

This comprehensive test plan has been generated dynamically by the ADK 2.0 Test-Planning Agent. It outlines the hierarchical user journeys, a deep scenario matrix, risk-based priorities, and semantic locators grounded in the web accessibility tree.

---

## 1. Hierarchical Journey Mapping

The Singapore Healthspan Simulator is a public web tool designed to educate users on their healthspan and morbidity gap, offering personalized simulations and actionable insights based on lifestyle and clinical factors.

## 1. Goals

1.  **G1: Simulate Personal Healthspan:** User obtains a personalized calculation of their projected healthspan and morbidity gap.
2.  **G2: Identify Healthspan Improvement Opportunities:** User understands how specific lifestyle and clinical changes can improve their healthspan.
3.  **G3: Grasp Simulation Methodology:** User understands the scientific basis, data sources, and calculation details underpinning the simulator's results.
4.  **G4: Initial Product Exploration:** User successfully navigates through the site to discover its features and purpose.
5.  **G5: Customize User Experience:** User can switch the interface language to their preference.

## 2. Checkpoints

Checkpoints are reusable blocks of user interaction or system functionality.

*   **C1: Access Landing Page**
    *   **Description:** User lands on the product's homepage.
    *   **PRD Reference:** 5.1 Site Structure (`/`)
    *   **DOM Reference:** `/` page (title: "Singapore Healthspan Calculator | Predict Your Healthy Years", description)
*   **C2: Select Language Preference**
    *   **Description:** User chooses between English (EN) and Simplified Chinese (中文) for the interface.
    *   **PRD Reference:** 1.3 Core Value Proposition (Localised), 5.1 Shared Chrome (SiteNav with locale toggle)
    *   **DOM Reference:** `button:has-text('EN')`, `button:has-text('中文')` (present on all pages)
*   **C3: Navigate to Simulator**
    *   **Description:** User clicks a call-to-action to access the interactive healthspan calculator.
    *   **PRD Reference:** 5.1 Site Structure (`/`, `/explore`)
    *   **DOM Reference:** `a[href='/simulator']` (e.g., "Try Simulator \u2192" button from `/` or `/explore`)
*   **C4: Input Demographics (Sex & Age)**
    *   **Description:** User provides their sex and current age, forming the baseline for the simulation.
    *   **PRD Reference:** 3.1 Baseline Stratification, 4. API Contract (`user_profile.sex`, `user_profile.current_age`), 5.2 Key Components (ControlPanel, custom stepper)
    *   **DOM Reference:**
        *   `input#current_age` (spinbutton) with `button:has-text('\u25b2')` (increment), `button:has-text('\u25bc')` (decrement)
        *   `input[name='sex']` (radio group with labels: "Male", "Female")
*   **C5: Configure Lifestyle Factors**
    *   **Description:** User sets their values for various lifestyle factors: smoking, physical activity, BMI, alcohol, sleep, diet, and social connection. For smoking and physical activity, conditional inputs for 'change age' may appear.
    *   **PRD Reference:** 3.2 Factor Set, 3.6 Time Dimension, 4. API Contract (`user_profile.lifestyle`), 5.2 Key Components (ControlPanel)
    *   **DOM Reference:**
        *   Smoking: `input[name='smoking']` (radio: "Non-smoker", "Active smoker")
        *   (Implicit): `smoking_change_age` input (spinbutton, conditionally revealed if "Active smoker" is selected)
        *   Physical Activity: `input[name='physical_activity']` (radio: "Sedentary", "Moderate", "Active")
        *   (Implicit): `physical_activity_change_age` input (spinbutton, conditionally revealed if "Sedentary" or "Moderate" is selected, as per PRD 3.6 for "worst state")
        *   BMI: `select#bmi` (combobox with options: "normal", "overweight", "obese")
        *   Alcohol: `select#alcohol` (combobox with options: "none_or_low", "moderate", "heavy")
        *   Sleep: `input[name='sleep']` (radio: "Normal (7\u20139h)", "Short (<6h)")
        *   Diet: `input[name='diet']` (radio: "Healthy", "Poor")
        *   Social Connection: `input[name='social_connection']` (radio: "Connected", "Isolated")
*   **C6: Configure Clinical Factors**
    *   **Description:** User sets their status for clinical markers, specifically blood pressure.
    *   **PRD Reference:** 3.2 Factor Set, 4. API Contract (`user_profile.clinical`), 5.2 Key Components (ControlPanel)
    *   **DOM Reference:** `input[name='blood_pressure']` (radio: "Normal (<130/80)", "High (\u2265130/80)")
*   **C7: View Core Simulation Results**
    *   **Description:** User observes the calculated predicted healthspan, predicted morbidity period, and a visual representation on the LifeCalendar.
    *   **PRD Reference:** 2.3 Request Flow (`{metrics, calendar}`), 3.7 Rounding Contract, 5.2 Key Components (HealthspanCard, LifeCalendar)
    *   **DOM Reference:** (Rendered output from HealthspanCard and LifeCalendar components - no direct DOM selectors for values in input)
*   **C8: Review Top Leverage Recommendations**
    *   **Description:** User identifies the single lifestyle factor modification with the largest potential healthspan gain.
    *   **PRD Reference:** 1.3 Core Value Proposition (Actionable), 2.3 Request Flow (`{leverage}`), 5.2 Key Components (LeverageCard)
    *   **DOM Reference:** (Rendered output from LeverageCard component)
*   **C9: Examine Detailed Audit Ledger**
    *   **Description:** User expands a section to review the step-by-step breakdown of how the healthspan was calculated, including all tiers of logic.
    *   **PRD Reference:** 1.1 What It Is (structured audit ledger), 1.3 Core Value Proposition (Explainable), 2.3 Request Flow (`{audit_ledger}`), 5.2 Key Components (AuditLedgerPanel)
    *   **DOM Reference:** (Expandable component for AuditLedgerPanel - likely a button or heading to toggle visibility)
*   **C10: Navigate to Explore Science Page**
    *   **Description:** User clicks a link to access the page detailing the scientific background and methodology of the simulator.
    *   **PRD Reference:** 5.1 Site Structure (`/explore`), 5.1 Shared Chrome (SiteNav)
    *   **DOM Reference:** A link with `href='/explore'` (implied in `SiteNav`)
*   **C11: Interact with Scientific Explanations**
    *   **Description:** User explores visual explanations and data on the "Explore the Science" page.
    *   **PRD Reference:** 5.1 Site Structure (`/explore`)
    *   **DOM Reference:** `input#explore-smoking` (range), `input#explore-metabolic` (range), `input#explore-activity` (range)

## 3. Journeys Map

### Journey 1: Basic Healthspan Calculation

*   **Description:** A first-time user quickly calculates their healthspan based on their current lifestyle and demographic inputs.
*   **Goals Achieved:** G1 (Simulate Personal Healthspan)
*   **Path:**
    1.  `C1: Access Landing Page`
    2.  `C3: Navigate to Simulator`
    3.  `C4: Input Demographics (Sex & Age)`
    4.  `C5: Configure Lifestyle Factors`
    5.  `C6: Configure Clinical Factors`
    6.  `C7: View Core Simulation Results`

### Journey 2: Identify Healthspan Improvement Areas

*   **Description:** A health-conscious user calculates their healthspan and then seeks specific recommendations on which lifestyle change would have the biggest impact.
*   **Goals Achieved:** G1 (Simulate Personal Healthspan), G2 (Identify Healthspan Improvement Opportunities)
*   **Path:**
    1.  `C1: Access Landing Page`
    2.  `C3: Navigate to Simulator`
    3.  `C4: Input Demographics (Sex & Age)`
    4.  `C5: Configure Lifestyle Factors`
    5.  `C6: Configure Clinical Factors`
    6.  `C7: View Core Simulation Results`
    7.  `C8: Review Top Leverage Recommendations`

### Journey 3: Validate Simulation & Understand Logic

*   **Description:** A user calculates their healthspan and then delves into the audit trail to understand the step-by-step reasoning behind the results.
*   **Goals Achieved:** G1 (Simulate Personal Healthspan), G3 (Grasp Simulation Methodology)
*   **Path:**
    1.  `C1: Access Landing Page`
    2.  `C3: Navigate to Simulator`
    3.  `C4: Input Demographics (Sex & Age)`
    4.  `C5: Configure Lifestyle Factors`
    5.  `C6: Configure Clinical Factors`
    6.  `C7: View Core Simulation Results`
    7.  `C9: Examine Detailed Audit Ledger`

### Journey 4: Scientific Exploration & Subsequent Simulation

*   **Description:** A user starts by exploring the scientific basis of the simulator and its data sources, then decides to try out the simulation tool.
*   **Goals Achieved:** G3 (Grasp Simulation Methodology), G1 (Simulate Personal Healthspan)
*   **Path:**
    1.  `C1: Access Landing Page`
    2.  `C10: Navigate to Explore Science Page`
    3.  `C11: Interact with Scientific Explanations`
    4.  `C3: Navigate to Simulator` (from the "Try Simulator" CTA on `/explore`)
    5.  `C4: Input Demographics (Sex & Age)`
    6.  `C5: Configure Lifestyle Factors`
    7.  `C6: Configure Clinical Factors`
    8.  `C7: View Core Simulation Results`

### Journey 5: Comprehensive Engagement (Advanced User)

*   **Description:** An engaged user explores all aspects of the simulator, from initial calculation to understanding the underlying science, recommendations, and audit details, potentially across different languages.
*   **Goals Achieved:** G1, G2, G3, G4, G5
*   **Path:**
    1.  `C1: Access Landing Page`
    2.  `C2: Select Language Preference` (e.g., switch to Chinese)
    3.  `C3: Navigate to Simulator`
    4.  `C4: Input Demographics (Sex & Age)`
    5.  `C5: Configure Lifestyle Factors` (including conditional change ages)
    6.  `C6: Configure Clinical Factors`
    7.  `C7: View Core Simulation Results`
    8.  `C8: Review Top Leverage Recommendations`
    9.  `C9: Examine Detailed Audit Ledger`
    10. `C10: Navigate to Explore Science Page`
    11. `C11: Interact with Scientific Explanations`
    12. (Optional: `C3: Navigate to Simulator` again to try new inputs based on learned science)

## 2. Deep Scenario Matrix (Happy, Sad, and Edge Paths)

As an expert QA Engineer focused on boundary analysis and risk-based testing, I have analyzed the provided Goals, Checkpoints, and Journeys Map for the Singapore Healthspan Simulator. Below is a comprehensive scenario matrix, categorized and prioritized, to ensure thorough testing of the application's functionality, usability, and robustness.

The prioritization considers:
*   **Priority 0 (Critical Path):** Scenarios essential for the core functionality of the simulator (G1), directly impacting healthspan calculation and primary results display.
*   **Priority 1 (Important Path):** Scenarios covering key secondary features (G2, G3) that add significant value, critical input variations, or potential high-frequency changes. Also includes error handling for core inputs.
*   **Priority 2 (Secondary Path):** Scenarios for UI/UX elements, less frequent interactions, non-core features (G4, G5), or detailed boundary/accessibility checks.

### Scenario: Calculate & View Core Simulation Results (Healthy Male, 40)

*   **Pre-conditions:**
    *   The application is accessible at its base URL.
    *   The browser session is clean, with no prior simulator state.

*   **Synthetic Data Definitions:**
    *   `gender`: "Male"
    *   `age`: 40
    *   `smoking_status`: "Non-smoker"
    *   `physical_activity`: "Moderate"
    *   `bmi_category`: "Normal BMI (18.5-24.9)"
    *   `alcohol_intake`: "None or Low"
    *   `sleep_duration`: "Normal Sleep (7-8 hrs)"
    *   `diet_quality`: "Healthy Diet"
    *   `social_connections`: "Connected Social"
    *   `blood_pressure`: "Normal (<130/80)"

*   **Test Steps:**
    1.  **Navigate to Landing Page:**
        *   Action: Go to the base URL (`/`).
        *   Expected Outcome: The page title "Singapore Healthspan Simulator" and the "Try Simulator" button are visible.
    2.  **Start Simulator:**
        *   Action: Click on the `simulator_start_button`.
        *   Expected Outcome: The simulator's "Your Demographics" section is displayed.
    3.  **Input Demographics:**
        *   Action: Select `gender_male_radio`.
        *   Action: Fill `age_input` with `40`.
        *   Action: Click `simulator_next_button`.
        *   Expected Outcome: The "Lifestyle Factors" section is displayed.
    4.  **Configure Lifestyle Factors:**
        *   Action: Select `smoking_non_smoker_radio`.
        *   Action: Select `physical_activity_moderate_radio`.
        *   Action: Select `bmi_normal_radio`.
        *   Action: Select `alcohol_none_low_radio`.
        *   Action: Select `sleep_normal_radio`.
        *   Action: Select `diet_healthy_radio`.
        *   Action: Select `social_connected_radio`.
        *   Action: Click `simulator_next_button`.
        *   Expected Outcome: The "Clinical Factors" section is displayed.
    5.  **Configure Clinical Factors & Calculate:**
        *   Action: Select `blood_pressure_normal_radio`.
        *   Action: Click `calculate_healthspan_button`.
        *   Expected Outcome: A loading indicator is briefly visible, then the "Your Healthspan Results" section is displayed.
    6.  **View Core Simulation Results:**
        *   Action: Verify `healthspan_result` is visible.
        *   Action: Verify `morbidity_gap_result` is visible.
        *   Expected Outcome: The predicted Healthspan and Morbidity Gap are displayed as positive numerical values, reflecting a healthy profile. No error messages are present.

*   **Declarative Intent Verification:**
    *   The user can successfully complete a full simulation with a healthy profile.
    *   The simulator accurately calculates and presents core healthspan metrics for the given inputs.
    *   The application flow is smooth and free of UI errors or unexpected states.
